# C++ 风格（`cxx/` 下自研的三个库）

来源：[Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html)
（中文对照：<https://zh-google-styleguide.readthedocs.io/en/latest/google-cpp-styleguide/>）。
标「基线」的是该指南原文规则，标「本项目」的是本仓库叠加的决定。

适用范围：**只约束 `cxx/{webview,quickjs,ffmpeg}/` 下我们自己的源码**
（`webview.cpp` / `quickjs.cpp` / `ffmpeg.cpp` 三个文件，没有自研头文件）。
下面这些**不在范围内**，风格不由我们决定，**也不要对它们"顺手格式化"**：

- `cxx/ffmpeg/ffmpeg/`、`cxx/quickjs/quickjs/` —— 上游 **submodule**；
- `cxx/webview/sdk/` —— 微软 WebView2 SDK 的随附头文件（`WebView2.h` 六万多行）。

（根 `AGENTS.md` 对 submodule 本来就有禁区，这里是同一条在风格上的体现。）

## 命名（基线）

| 实体 | 规则 | 例 |
|---|---|---|
| 文件 | 全小写，用 `_` 分隔；头文件 `.h`、源文件 `.cc`、待包含片段 `.inc` | `my_useful_class.cc` |
| 类型（类/结构体/typedef/枚举/类型模板参数） | 每词首字母大写，**不含下划线** | `UrlTableTester`、`UrlTableErrors` |
| 变量（含函数参数、数据成员） | 全小写、`_` 连接；**类成员变量末尾再加一个 `_`**（结构体成员不用） | `table_name`、`table_name_` |
| 常量（`constexpr` / `const`，以及所有静态存储期变量如全局、静态） | **`k` 开头 + 混合大小写** | `kDaysInAWeek` |
| 函数 | 每词首字母大写、无下划线；取值/设值函数与变量同名 | `AddTableEntry()`、`count()`、`set_count()` |
| 命名空间 | 全小写；顶级名取项目名 | `websearch::index_util` |
| 枚举值 | **优先**常量风格（`kErrorOutOfMemory`），宏风格（`OUT_OF_MEMORY`）也可接受 | `kOK = 0` |
| 宏 | 全大写 + `_`（但**通常不该用宏**） | `MY_MACRO_THAT_SCARES_SMALL_CHILDREN` |

- 首字母缩写视作一个单词：`StartRpc()`，**不是** `StartRPC()`。
- 命名要有描述性，**少用缩写**：`price_count_reader` 好，`n` / `nerr` / `wgc_connections` 差。
- 通用规则：命名风格的意义在于**不用查声明就能知道名字代表什么**。风格本身有一定随意性，
  但**一致性比个人偏好重要**。

## 格式（基线）

- **每行不超过 80 字符**。（例外：无法美观断行的注释行、含长路径的 `#include`、头文件保护。）
- **只用空格，块缩进每级 2 个空格、续行 4 个空格，不使用制表符**（与 Kotlin / Gradle 同一套，
  见 [`SKILL.md`](../SKILL.md) 的「缩进」一节）。← 现有 `webview.cpp` 是 4 空格块缩进，属遗留；
  新代码按 2 空格，改到哪一行就顺手对齐那一处，**不要为此整篇重排**。
- 左大括号：
  - 函数**定义**的左大括号可以另起一行；其余（函数声明、类/结构体/枚举声明、各种语句）
    **置于行尾**；**所有右大括号独立成行**（除非与左大括号同一行是空的实现体）。
  - 右圆括号与左大括号之间**总有一个空格**。
- 函数：返回类型与函数名同行；左圆括号总与函数名同行，且**函数名与左圆括号之间无空格**；
  括号内两侧不留空格；参数放不下时**换行后缩进 4 个空格**。
- 函数调用：能一行写完就一行；否则换行后**与第一个实参对齐**，或另起一行缩进 4 格。
- 类：访问控制块顺序 `public:` → `protected:` → `private:`，每个**缩进 1 个空格**；
  除第一个外的关键词前空一行；关键词后不留空行。
- 构造函数初始化列表：能一行就一行；否则置于冒号后并缩进 4 格；成员各占一行时逐行对齐。
- 水平留白：赋值与其它二元运算符两侧有空格；圆括号内侧不留空格；一元运算符与操作数之间不留空格
  （`x = -5;`、`++x;`）。`.` 与 `->` 两侧不留空格；`*` / `&` **只在一侧留空格**（靠左靠右皆可，
  **同一文件内保持一致**）。
- 布尔表达式超长时，`&&` / `||` **统一放在行尾**。
- 头文件保护：全大写、路径单词用 `_` 连接、以 `_H_` 结尾（`FOO_BAR_BAZ_H_`）。
- `#include` 顺序：关联头文件 → 空行 → C 系统头 → 空行 → C++ 标准库头 → 空行 → 其他库 → 空行 →
  本项目头文件；**每组内按字母序**。项目自己的头文件用 `""`，系统/标准库用 `<>`。
- 头文件必须**自包含**（能独立编译）。

## 作用域与组织（基线）

- 代码**必须**放进命名空间；**禁止** `using namespace`；**禁止** inline namespace；禁止往 `std` 里加东西。
- `.cc` 里不对外暴露的定义，放**匿名命名空间**或声明为 `static`（头文件里两者都禁止）。
- 命名空间内的代码**不额外缩进**；多行命名空间的结束处加注释（`}  // namespace foo`）。
- 优先**返回值**而不是输出参数；仅输入参数放在输出参数**之前**。
- 函数体短于约 10 行才可以定义在头文件里，且必须 ODR 安全（`inline` / 模板 / 类内定义）。
- `struct` 只用于**纯数据被动对象**且字段全 public、无跨字段不变量；其余一律 `class`。

## 错误处理（基线 + 本项目）

- **基线：不使用 C++ 异常**（Google 明文）。替代手段是**错误码 + 断言**。
  （Windows 代码在该指南里有例外，但本项目**不用**那个例外。）
- 本项目现状与之一致：自研 C++ 一律**返回码 / 空指针**表示失败，不抛 C++ 异常 ——
  继续这样做。**绝不让异常穿过 JNI 边界**（穿过会导致未定义行为）。
- 构造函数里避免调用虚函数；避免"无法报错的初始化失败"，必要时改用工厂函数或 `Init()`。
- 该加 `noexcept` 时就加（如移动构造）。

## 本项目

- **JNI 入口命名不由 Google 指南规定**，由 JVM 约定决定：符号必须是
  `Java_<包名下划线化>_<类名>_<方法名>`，**不带签名**。这条比风格重要得多 ——
  改了 Kotlin 侧签名却用旧 dll 不会报错，只会参数错位（见 [`cxx/AGENTS.md`](../../../../cxx/AGENTS.md)）。
- 现有三个库都是**单文件成库**（`webview.cpp` / `quickjs.cpp` / `ffmpeg.cpp`），没有自研头文件。
  新增同类小库可以照此办；但一旦要拆，就按基线的 `.h` / `.cc` 规则拆，不要一边拆一边留半截。
- 现有三个文件**平铺、没有 namespace**，内部链接用 `static`。**不要求回改它们**；
  但**新增的共享库**建议按基线用命名空间包裹整体。
- 注释语言与格式：**中文 + 行注释 `//` + 文档注释 `/** … */`**，完整规则在
  [`comments.md`](./comments.md)（四种文件同一套）。现状并不统一：`webview.cpp` 以中文为主、
  `quickjs.cpp` 近乎全英文、`ffmpeg.cpp` 几乎无注释 —— 新代码一律按 `comments.md` 写。
- 现有 `webview.cpp` 里用宏 `WV_JNI(...)` 生成 JNI 函数名，另两个库手写全名。**新增时照抄同一个库
  现有的做法**，不要在一个文件里混用两种。

# 注释：语言与格式（四种文件同一套）

**一套格式，`.kt` / `@Composable` / `.cpp` / `*.gradle.kts` 共用。**
标「基线」的是官方指南原文（出处见文末），「本项目」是本仓库叠加或**覆盖**的决定；冲突以「本项目」为准。

适用范围同 [`SKILL.md`](../SKILL.md)：**只管我们自己的代码** —— `cxx/ffmpeg/ffmpeg/`、
`cxx/quickjs/quickjs/`（上游 submodule）与 `cxx/webview/sdk/`（微软 SDK 头文件）**不在其中**。

## 一、语言：中文（本项目）

- **注释一律中文。**
- 但**标识符、路径、命令、任务名、报错与日志原文保持英文原样**，不要翻译 —— 翻成中文会变成
  "看着差不多"然后抄错（根 `AGENTS.md` 同款要求）。
- **术语不硬译**：`QuickJS`、`WebView2`、`JNI`、`dll`、`Modifier`、`dispatcher` 照写。
- 中文注释用**全角标点**（`，。；：`）；其中的代码片段、路径、符号用反引号包住、原样保留。
  —— 官方没有中文注释的规则，这条是本项目的补充。

## 二、形式：行注释 `//`（本项目统一）

| 用途 | 写法 | 不要 |
|---|---|---|
| 普通注释 | `// 说明`（`//` 后**一个空格**） | `/* … */` 块注释 |
| 多行说明 | 连续多行，**每行都带 `//`** | 拿 `/* … */` 拼一个块 |
| 行尾注释 | 代码 + **两个空格** + `// 说明` | 用 tab 或竖排对齐 |

- **`/* … */` 只允许一处例外**：文档注释（下一节）。
- ⚠️ **别把这条当成 Google 的要求**：Google C++ 指南的原话是「**`//` 或 `/* */`，统一就好**」
  （`//` 更常用）—— 也就是两种都行。"只用 `//`"是**本项目**为了四种文件同形而定的，
  不是官方规则。**行尾空两格**倒是官方原话（§8.6「在行尾空两格进行注释」）。
- **不做竖排对齐**：Kotlin 官方明确"避免任何形式的水平对齐"；Google 对**行尾注释**是**容许**
  对齐的（§8.6），但本项目不采用 —— 中文注释对齐更难看，而且四种文件要同一套。

## 三、文档注释：`/** … */`（KDoc 形态，四种文件同形）

只给**对外契约、或"不读就会用错"的声明**写：

```kotlin
/**
 * 一句话说清它是什么、为什么是这个形状。
 * 第二段才写不显然的约束。
 */
```

- Kotlin 就是官方 KDoc。**C++ 与 Gradle KTS 用完全相同的形状**（`/**` 单独一行、后续每行 `*` 开头、
  ` */` 单独一行），这样四种文件看起来一致。
- **一句话能说清就用单行**：`/** 短说明。 */`
- **不写 `@param` / `@return` 标签**（Kotlin 官方建议把描述写进正文并链接参数）。
  本项目**不引入 Doxygen**，所以 C++ 也不用 `@brief` / `\param` 那一套。
- 分界：**文档注释**解释"这是什么、怎么用"；**普通注释**解释"为什么这么写"。两者都不复述代码在做什么。
- **粒度**：Google 要求给**每个类**、**几乎每个函数声明**都写注释（§8.3 / §8.4）；
  **本项目不要求这个粒度** —— 只强制上面那两类，其余由改动者判断。注释比代码还长是不好的信号。

## 四、写什么、不写什么

- **写「为什么」与不显然的约束**，不写「代码在做什么」的复述。官方原话很重：
  「**永远不要**用自然语言翻译代码作为注释」「注释应当解释代码*为什么*要这么做和代码的目的」，
  并且「**要假设读代码的人 C++ 水平比你高**」（§8.6）。
  - 反例：`// 遍历列表` 配 `for (x in list)`。
  - 正例：`// 必须同步，否则 JS 侧会拿到已释放的 handle`。
- **写成完整句子**：正确的大小写、以句号结尾（官方 §8.7）。简短的行尾注释可以随意些。
- **不写会腐烂的信息**：`@author`、日期、"修改记录"。要追溯就看 git。
  （官方只讲"重大修改时**考虑**删掉原作者信息"，并没有禁止——所以这条是**本项目**的更严决定。）
- **不留注释掉的死代码**：删掉，git 历史里有。
- **不引用已经不在的东西**：注释里提到的类 / 函数 / 依赖，得能在**当前仓库或当前依赖树**里找到。
  一条依赖被整个移除后，注释里残留的「以前用的是 X」只会让人去仓库里翻一个不存在的东西 ——
  要么删掉这句，要么改成讲现状。例外：**明确写了「已删除 + 出处」的防回归说明**
  （如 `webview.cpp` 里的 `ScopedThreadInput`），那是刻意留的警告，不算过时引用。
- **待办写进根 [`TODO.md`](../../../../TODO.md)**（需要长期跟踪的）；代码里的临时标注写
  `// TODO: 中文说明`，不要派生 `NOTE` / `FIXME` / `XXX` 一堆前缀。
  （官方 §8.8 的形式是 `// TODO(身份): 说明`；本项目单人开发，省掉括号。官方那条本身很值得照抄：
  **`TODO` 写全大写**。）
- **注释与它说明的代码同级缩进**。

## 五、现状（不是规范，只是记录）

现有注释**不统一**：`webview.cpp` 以中文为主（499 行中文 / 190 行 ASCII），`quickjs.cpp`
近乎全英文（2 / 102），部分 `.kt` 混英文。全仓含中文 1519 行、纯 ASCII 788 行
（含 `*`、`*/` 这类块结构行，会略微高估 ASCII 一侧）。

**新注释按本文件写；改到旧注释就顺手改成中文。存量统一是一次独立提交，见根 `TODO.md`。**

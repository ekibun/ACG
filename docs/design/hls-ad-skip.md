# HLS 插播广告跳过的判据与落点

> **已落地。** 改 `cxx/ffmpeg/patches/hls.sed` 的广告探测、或再评估「每片都判 / 播放列表代理 /
> 播放侧丢帧 / 单调 PTS」这类方案之前先读本文：判据的推导、被否决的方案、代价与实测都在这里，
> 源码里只留裸约束与指针。
>
> 前置：[playback-invariants.md 1.7](../development/playback-invariants.md)（包的 `pts/dts` 已按分片
> 平移到声明轴）。判定必须取**平移前**的媒体时间，所以它和 1.7 长在同一处。

## 一、问题

采集站在分片边界拼入广告。广告是独立转码的，媒体时间从 ≈1.48 s 重新起算，而声明轴（`EXTINF`
累加）把广告的时长算在内。1.7 把每个分片平移到声明轴之后，广告和正片在播放侧**看不出任何差别**
——`frame.timeStamp` 连续、进度条连续，症状消失的同时也失去了识别能力。

所以判定只能发生在平移那一刻，依据是平移前的那两个数：该片的声明起点、该片首包的媒体时间。

## 二、判据：标记处回跳 + 找得到接续才跳

素材观察：**广告在播放列表前后两侧都有 `#EXT-X-DISCONTINUITY`**。ffmpeg 的 `hls.c` 上游完全
不解析这个 tag，所以要自己认（`hls.sed` 4.1c/4.1d）。

### 2.1 触发：只在标记片、且媒体时间回跳

```
触发 ⟺ 该片前面紧挨 #EXT-X-DISCONTINUITY
      且 上一包（同一条流）媒体时间 − 本片首包媒体时间 > 5 s
```

广告独立转码 ⇒ 在标记处媒体时间从 ~1.48 重新起算 ⇒ 回跳量约等于它所在的声明位置。
正片在标记处的媒体时间是连续的（编码参数变化不影响时间轴），所以「标记处出现大回跳」
本身就说明这里换了一条时间轴。

**5 s 门槛的作用**是把盲区压到声明 6 s 之后（回跳量最大就是声明位置，广告首包在 1.4 s 附近）。
再往下压没有意义：`< 1.4 s` 等于「任何回跳」，而编码器起点、片间舍入都在这个量级。

门槛降低之后，进入判定的场景里多了「回退 5~30 s 的段落」。如果这种段的落点恰好接得回基线，
2.2 就会把它当成广告跳掉——能不能兜住只取决于出口那一步。这里没有再叠「起点是否在新时间轴
开头」这类准入限制：样本里没有那种形态，加了只会挡掉合法广告（时间轴从 20 s 以上起算的那种）。

**基线按流分开存（`ff_last_media_us[8]`）。** 字幕流和独立音轨的 PTS 能和视频差几秒，
共用一个基线会让判定在音视频交替处反复误触发——5 s 门槛下这会变成每片扫一轮。

### 2.2 裁决：先找接续点，再跳

怀疑之后不立刻跳，而是往后扫**标记片**，逐个读它的首包。「往后扫多远」是按**单跳**算的：
相邻两个标记片的声明距离超过 60 s 就停 —— 中间隔着一整段主片，说明不是同一段插播。

| 候选片的媒体时间 | 结论 |
| --- | --- |
| `abs(媒体 − 基线) ≤ 500 ms` | 接上了 → 跳到这里，广告到此为止 |
| `媒体 > 基线 + 500 ms` | 跑过基线了 → **放弃** |
| `媒体 ≤ 上一个候选点的媒体时间` | 媒体时间回退，这里已经换了一段内容 → **放弃** |
| 其余（媒体在继续往前） | 继续看下一个标记 |
| 相邻标记片相隔超过 60 s，或扫到列表末尾 | **放弃**，退回广告起点照常播 |

中间几段只要求**媒体时间单调往前**，不拿声明时长去外推「预期媒体时间」：同一段广告里它本来
就跟着走，而 `EXTINF` 与片内实测时长常有几十毫秒到几百毫秒的出入，外推反而要再配一个容差。
回退则是一条明确的界线——同一段里不会出现。

这就是「从广告开始也不会误伤正片」的来源：**没有确认的接续点就一律不跳**。代价是没标的广告
会被整份放过（见第六节）。

500 ms 这条容差不能放宽：2 s 的分片用 2 s 容差，下一片正片正好落在容差边界上，会被当成接续点，
中间那一整片就被删了。

## 三、被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 播放列表代理改写（animeko 的做法） | 要起本地 socket、要自己的 m3u8 解析器、要 `2KB × 组数` 的 Range 探测。ACG 的 demuxer 就在进程内，判定与跳段在同一层做，这些成本买不到额外信息 |
| 每片都判（绝对偏移 `偏移 > max(30s, 声明/3)`） | 召回高（没标记的拼接也抓），但正片自身的回跳也会中，容差还得按「累计广告时长」去撑。素材上广告都带标记，于是用标记换精度 |
| 播放侧丢帧（Kotlin 判、丢包/丢帧） | 丢掉的字节仍要下载解码；包已被平移，播放侧看不到回跳，得再把媒体时间透传一遍 |
| 单调 PTS（任何回跳都丢） | 真实线路里正片自己会回跳：animeko 样本中下集预告的媒体时间比前一段末尾小 **124 s**，会被整段吃掉。回跳 ≠ 广告 |
| `abs(声明 − 媒体)` | 正片剪开重拼时媒体领先声明轴，差值为负，`abs` 把它也算成可疑——该样本的 G2 超前 137 s |
| 把媒体时间挂在 `AVPacket` 上 | `opaque` 是 `void*`，32 位进程装不下微秒级 int64；`opaque_ref` 要么每包 `av_buffer_alloc`、要么只能带片内常量；`pos`/`time_base` 是公共字段 |
| 判据写在 Kotlin | 判定要用**平移前**的媒体时间，而读包是 100 包预读 + 通道，消费端拿到的包早已错配 |

## 四、落点

### 4.1 跳段在 `hls.c`

分段推进就是一个 `cur_seq_no`。判定成立时 `ff_hls_jump_to()` 关掉当前片的 IO、清空内层解复用器的
缓冲、把 `cur_seq_no` 设到目标片，下一次读就从那片开头开始 —— 广告主体**零下载、零解码**。

扫描候选点每次是一次 io 复位 + 读一个包。**接上时不能丢那个包重读**：扫描阶段已经用
`av_read_frame` 把它读走了，`av_packet_unref` 只释放包、不回退读位置，`continue` 之后拿到的
是这一片的**第二个**包 —— 首帧 IDR 就没了，后面整片都没有参考帧（症状是跳过点之后花屏，
一直到下一个 IDR）。

所以这个函数只剩两种结局：

| 返回 | 含义 | 调用方 |
| --- | --- | --- |
| `FF_AD_PROCEED` | 用当前 `pls->pkt` 继续（跳过时它已经是目标片首包） | 按当前片重算声明起点与媒体时间，平移 |
| `FF_AD_RESTART` | 位置挪走了，但那一片的包还没读 | `continue`，重新 `av_read_frame` |

不区分「跳过」和「没跳过」：没跳时 `cur_seq_no` 与 `pkt` 都没变，那次重算是幂等的。

### 4.2 跳过区间不上报，由上层从「声明时间空档」自己推

1.7 平移之后声明轴逐段连续，相邻包正常只差一帧。跳段会在交给上层的包序列里留下等于广告时长的空档，
所以上层只要包级 `pts`（通用字段）：`FFPlayer` 按流比相邻包，`> 1 s` 就记一条待发。

不要用 `AVPacket.flags` 的位去标记「这里跳过了广告」，那是公共语义（`DISCARD` 已占「让解码器丢掉」）。
`flags` 只原样透传：`AV_PKT_FLAG_KEY` 用来确认接上的是关键帧，不承载业务含义。

直播 / EVENT 播放列表不走平移，声明轴不保证连续，这条推断只在走位移路径的 VOD 上启用。

### 4.3 提示的时机：等画面到

读包是 100 包预读，读位置比画面领先数秒 —— 读到空档就发事件会让提示比画面早好几秒。
⇒ 读到空档只进待发列表，等**第一帧显示到 `to` 之后**才发 `Event.AdSkipped(from, to)`；seek 清空。

### 4.4 回退：整流关掉

```c
/* hls.sed 第 5 条 */ int acg_hls_set_skip_ad(AVFormatContext *s, int on);
```

回退 = `setSkipAd(false)` → `seekTo(from)`，之后这集所有广告照常播（用户自己的选择）。
不做「按区间放行」的状态机，也就不存在「放行没覆盖到、按了像没反应」。

### 4.5 纯视频流要自己抬时钟

时钟由音频帧推进（`flushFrame` 只对音频返回时间戳）。纯视频流没有音频，跳过之后
`frame.timeStamp` 比 `pts.now()` 大了整整一个广告时长，送显门限会白等：实测 `10 s → 18 s`
从 3 s 变成 7 s 多。所以没有音频流时，第一帧越过空档末端就 `pts.update(frame.timeStamp)`。

「越过」要留容差：B 帧重排会让跳过后第一帧的时间戳比记录的空档末端**早一两帧**（实测 42 ms），
用严格 `>=` 会漏掉它。`AD_SKIP_EDGE_US = 500 ms`。

## 五、代价

- **额外请求 0**：判定在首个包到达时做，那一片本来就要读。
- 每个被跳过的广告片只读一个包（走 `HttpIO` 就是一块 32 KB）；扫描每个候选点一次 io 复位 + 一个包。
- 起播延迟 0（判定发生在播放途中，不在 open 时）。
- **门槛从 30 s 降到 5 s 只增加扫描次数，不增加误删**：删不删由 2.2 的接续点裁决，触发只代表
  「这里的时间轴断了」。扫描是串行的，所以慢源上每多一次候选点就是一次 RTT——这是「单跳 60 s」
  和「只扫标记片」的价值。
- 「开流时就探好」的代价参考：M 次请求 + M×32 KB，串行 M×RTT（真实源 100–300 ms）。M=8 约 1–2 s，
  M=60 要并发才有意义。轴不闭合、不需要提前知道，所以不买这个。

## 六、已知限制

1. **声明 6 秒之前的广告测不到**（回跳量最大就是声明位置，广告首包在 1.4 s 附近）。
2. **没标 `#EXT-X-DISCONTINUITY` 的拼接一律不跳** —— 刻意的精度取舍：宁可漏，不误删。
3. **标记不成对**（只标开头、或广告内部多一个标记）：靠逐个候选点验证处理；只标开头的那种会一路
   扫到「单跳超过 60 s」才退回，多花几次 io 复位。
4. **轴不闭合**：跳过时进度条 12→17.1 跳一下，`duration` 仍含广告。明确的设计选择。
5. **插在主片中间、前后都没有广告的内容段**（媒体时间回退 5 s 以上、落点又接得回基准）会被
   当成广告跳过。样本里没出现过这种形态；能兜住的只有「找不到接续点就退回」。
6. 跳过点上游的 mpegts 会打 `Packet corrupt`（跨段 continuity counter 跳变），属正常现象。

## 七、实测与用例

素材 `hls-ad`（`shared/src/jvmTest/resources/media/`）：主片 0–24 s，广告 12–17.1 s（媒体时间从
1.483 s 重新起算，回跳 11.9 s），之后主片接着自己的媒体时间走到 25.5 s；广告两端都有标记。
三个用例：

| 用例 | 开关 | 验什么 |
| --- | --- | --- |
| `HlsAdSkipTest.adSegmentsNeverReachTheCaller` | 默认开 | 广告三片的包一个都不到上层，声明轴只剩一个 ~5.1 s 空档；**接上的第一包是关键帧** |
| `HlsAdSkipTest.skipDoesNotStallPlayback` | 默认开 | `10 s → 18 s` 墙钟 < 6 s（纯视频流不抬时钟会到 7 s 多） |
| `HlsAdTimelineTest.framesStayContinuousAcrossAdBreaks` | `setSkipAd(false)` | 接缝 12 s / 17.1 s 两侧时间戳连续（平移本身，1.7） |

素材的广告就在声明 12 s 处，这本身就是 2.1 门槛降到 5 s 的证据：同一份列表在 30 s 门槛下
回跳 11.9 s 不够，广告会照播；按现在的门槛，声明轴上唯一空档是 `12.042 s → 17.183 s`，
末包 25.4 s。
